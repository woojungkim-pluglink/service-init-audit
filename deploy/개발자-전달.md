# [개발/IT 전달용] service-init-audit를 PC 없이 자동 실행되게 배포 요청

> PM(쿠이) → 개발/IT 담당자께. 아래만 해주시면 끝납니다. 코드·설명은 전부 준비돼 있습니다. **예상 30분.**

## 무엇
`service-init-audit` (Node.js + Playwright) 를 **클라우드에서 24시간 실행**되게 배포 → 현재 PM PC의 Windows 작업 스케줄러(08:05/17:05) 의존 제거. 매일 아침/저녁 충전소 서비스개시 검증 + Slack 알림 + (미운영 충전기) 자동 원격제어.

## 준비된 것 (레포 `deploy/` 폴더)
- `Dockerfile` — Playwright(Chromium) 포함. 그대로 빌드.
- `server.js` — `POST /run?slot=morning|evening` 트리거 웹훅(헤더 `x-trigger-secret`). 컨테이너 CMD.
- `n8n-service-init-audit.json` — n8n 스케줄(08:05/17:05 KST)→웹훅 호출 워크플로. (n8n에 이미 `qONFiRZ9EtBj3g3o`로 사전 생성돼 있음)
- `DEPLOY.md` — 상세 런북. `prod.env.example` — 주입할 환경변수 목록.
- 로그인은 audit의 기존 **브라우저 폼 로그인(`ensureSession`)**이 처리 → 별도 인증 작업 불필요.

## 해주실 일 (요약)
1. **빌드**: 레포 루트에서 `docker build -f deploy/Dockerfile -t service-init-audit .`
2. **호스트**: Cloud Run / Fly.io / 소형 VM 중 택1에 배포(메모리 2GB+). 외부 HTTPS URL 확보.
   - 상태 데이터(대시보드)는 `public/data`를 **퍼시스턴트 볼륨**에 마운트(히스토리 누적 + Vercel 배포). 자세히는 `DEPLOY.md` 3·4장.
3. **시크릿(env) 주입** (`deploy/prod.env.example` 키들 — 콘솔/CLI에서 직접):
   `TRIGGER_SECRET`(임의 강한 값), `PLINKCONNECT_USERNAME/PASSWORD`(PM에게 별도 안전 채널로 수령 — **채팅/문서에 평문 금지**), `SLACK_BOT_TOKEN`·`NOTIFY_SLACK_*`·`SLACK_CHANNEL_ID`, `GMAIL_CLIENT_ID/SECRET/REFRESH_TOKEN/USER`, `PM_GROUP_EMAILS`, `VERCEL_TOKEN`(대시보드 배포용), `PLINKCONNECT_BASE`, `DASHBOARD_URL`.
4. **n8n 연결**: n8n.pluglink.kr 워크플로 `qONFiRZ9EtBj3g3o`(또는 `deploy/n8n-service-init-audit.json` import)의 HTTP 노드 2개 → `url`을 2번 호스트 URL `/run?slot=morning`·`/run?slot=evening`로, 헤더 `x-trigger-secret`을 3번 값으로 교체. **Publish(Version name 입력) → Active.**
5. **검증**: `curl -X POST -H "x-trigger-secret: <값>" "https://<호스트>/run?slot=morning"` → 202 + 컨테이너 로그 확인 → 대시보드/Slack 갱신 확인.
6. **전환**: 정상 확인 후 PM PC의 작업 스케줄러 비활성화(`Disable-ScheduledTask service-init-audit-morning/-evening`) — 이중 실행 방지.

## 참고
- 충전기 원격제어(미운영→운영)는 실모드에서 실제 동작. 첫 실모드 실행 로그로 결과 확인 권장.
- 동시 실행은 server.js가 409로 차단(단일 브라우저 세션). 08:05/17:05 시간 분리 유지.
- 의문점은 `deploy/DEPLOY.md` 참고. 코드/로직은 검증 완료(`node --test` 96 pass).
